第 3 章 · 服务器实战：把 Linux 变成一台真正干活的服务器

前两章你学会了"操作"和"连接"。这一章开始做事：搭网站、跑服务、配数据库、做定时任务。
学完本章，你就拥有了"一个人搭出小型网站后端"的能力——这已经是初级运维工程师的看家本领。
预计学习时间：2-3 周。

3.1 先想清楚："服务器"到底是什么形态？

一台服务器上通常同时跑着好几样东西，它们分工合作：

用户浏览器
    │  (通过 80/443 端口访问)
    ▼
┌─────────────┐
│   Nginx     │  ← "前台接待员"：接收所有访客请求
└──────┬──────┘
       │ 静态文件它自己直接给；动态请求转给"后厨"
       ▼
┌─────────────┐
│  你的程序    │  ← "后厨"（Python/Go/Java 写的应用）
└──────┬──────┘
       │ 需要存数据时
       ▼
┌─────────────┐
│  数据库      │  ← "仓库"（MySQL/PostgreSQL）
└─────────────┘

这一章，我们要把"接待员、后厨、仓库"都亲手装一遍。 这就是云计算比赛的每日训练内容，也是所有互联网公司的基本架构。

3.2 Nginx 深入：从"会开"到"会配"

3.2.1 回顾一下（第 2 章装好的）

sudo systemctl status nginx      # 确认它在跑
curl http://localhost            # 确认能访问

3.2.2 Nginx 的配置文件在哪、怎么看

ls /etc/nginx/                   # 看 nginx 的"配置大本营"

关键文件：

/etc/nginx/nginx.conf            ← 主配置（一般不直接改）
/etc/nginx/sites-available/      ← 可用站点配置（我们在这写）
/etc/nginx/sites-enabled/        ← 已启用站点（能跑的配置）
/var/www/html/                   ← 网站文件默认放这里
/var/log/nginx/                  ← 日志（access.log 访问日志 / error.log 错误日志）
设计妙处：sites-available（仓库）和 sites-enabled（货架）分开。写好的站点先放"仓库"，想要它上线，就在"货架"里建一个快捷方式（软链接）。下线一个网站=删快捷方式，文件不丢。

3.2.3 写一个完整站点配置（手把手）

目标：搭一个"公司官网"，域名叫 mycompany.local（本地测试用），网站文件放 /var/www/mycompany。

第 1 步：建网站目录和首页

sudo mkdir -p /var/www/mycompany
sudo nano /var/www/mycompany/index.html

写入：

<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>我的公司</title></head>
<body>
  <h1>欢迎来到 ABC 公司</h1>
  <p>这是 Nginx 虚拟主机配置的练习站点。</p>
</body>
</html>

第 2 步：写站点配置

sudo nano /etc/nginx/sites-available/mycompany.conf

写入（每一行都给你注释，请一个词一个词读）：

server {
    listen 80;                        # 监听 80 端口（接收 HTTP 访问）
    server_name mycompany.local;      # 这个站点响应哪个域名
    root /var/www/mycompany;          # 网站文件放在哪里
    index index.html;                 # 默认首页文件名

    location / {                      # "当访客访问 / （根路径）时……"
        try_files $uri $uri/ =404;    # "先找这个文件，找不到再找同名目录，都没有就报 404"
    }

    access_log /var/log/nginx/mycompany.access.log;   # 访问日志记到哪
    error_log  /var/log/nginx/mycompany.error.log;    # 错误日志记到哪
}
看不懂 try_files 没关系——先记住这是"静态网站的标准三行"，以后每个站点都这么写。

第 3 步：启用站点（做快捷方式）

sudo ln -s /etc/nginx/sites-available/mycompany.conf /etc/nginx/sites-enabled/

（ln -s 源文件 快捷方式位置 = 创建软链接，像 Windows 的"桌面快捷方式"）

第 4 步：测试语法 → 重启 → 验证（标准四步，背下来）

sudo nginx -t                    # ① 测试配置语法（必须养成习惯！）
# 输出 syntax is ok / test is successful → 通过
sudo systemctl reload nginx      # ② 重新加载（reload 比 restart 更平滑，不断已有连接）

第 5 步：本地测试"假装访问这个域名"

curl -H "Host: mycompany.local" http://localhost

→ 应返回你写的"欢迎来到 ABC 公司"页面。

真正用浏览器访问：编辑你电脑的 hosts 文件（模拟 DNS）：

  • Windows：C:\Windows\System32\drivers\etc\hosts（用管理员权限的记事本编辑）
  • 加一行：你的服务器IP mycompany.local
  • 浏览器访问 http://mycompany.local → 成功！
🏆 你刚刚配置了一个"虚拟主机"——同一台服务器、同一个 80 端口，根据访问的域名返回不同的网站。 全世界几十万个网站共用服务器的原理就是这个。世界赛的 Nginx/HAProxy 考点从这里发芽。

3.2.4 "公司要多个网站"——再配一个

重复刚才的流程：建 /var/www/blog 目录、写 blog.conf（server_name 用 blog.local）、软链、nginx -t、reload、hosts 加一行 → 两个网站并存。体会"一份软件、多份配置"的复用思维。

3.2.5 看日志：网站出问题时它在"说话"

sudo tail -f /var/log/nginx/mycompany.access.log

另开一个窗口 curl -H "Host: mycompany.local" http://localhost，你能实时看到访问记录滚出来：

127.0.0.1 - - [16/Sep/2026:11:00:01 +0800] "GET / HTTP/1.1" 200 615 "-" "curl/7.81.0"

逐段读：谁访问的（IP）→ 什么时间 → 请求了什么 → 状态码（200 成功/404 没找到） → 返回了多少字节。

sudo tail -f /var/log/nginx/mycompany.error.log    # 出错时看这个

排错铁律：网站不正常 → 先看这两个日志。 90% 的问题日志里写得明明白白。

【出错了怎么办——Nginx 高频 5 坑】

  1. nginx: [emerg] unknown directive：配置写错（拼写/少了分号 ;）。nginx -t 会指出第几行。
  2. 访问到的是"Welcome to nginx"而不是你的页面：你的 server_name 没匹配上。检查①域名拼写②hosts 文件③有没有 reload。
  3. 改完配置没生效：忘了 reload。"改配置→nginx -t→reload→验证"是肌肉记忆。
  4. 403 Forbidden：网站文件的"读权限"不对，或目录里没有 index.html。
  5. 404 Not Found：路径不对——root 配置的目录里真的有你想要的文件吗？ls 去看。

3.3 让服务器"跑程序"：部署一个后端服务

静态网页只是开始。真正干活的是后端程序（接收请求、处理业务、返回数据）。我们用 Python 写一个超小服务，把"后端"这个东西摸清楚。

3.3.1 写一个最简单的 API 服务

sudo apt install -y python3-pip
mkdir -p ~/apps && cd ~/apps
nano memo.py

写入：

#!/usr/bin/env python3
# 一个简易"备忘录"API：把内容存到文件里
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import urlparse, parse_qs

MEMO_FILE = "/home/student/apps/memo.txt"   # 注意改成你的用户名！

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        query = parse_qs(urlparse(self.path).query)
        action = query.get("action", ["list"])[0]
        if action == "add":
            text = query.get("text", [""])[0]
            if text:
                with open(MEMO_FILE, "a", encoding="utf-8") as f:
                    f.write(text + "\n")
                self._reply("已添加: " + text)
            else:
                self._reply("用法: ?action=add&text=要记的内容")
        else:  # list
            try:
                with open(MEMO_FILE, encoding="utf-8") as f:
                    self._reply("备忘录:\n" + f.read())
            except FileNotFoundError:
                self._reply("还没有备忘录")

    def _reply(self, text):
        data = text.encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.end_headers()
        self.wfile.write(data)

HTTPServer(("0.0.0.0", 8000), Handler).serve_forever()

（看不懂每行没关系——这是"看得见摸得着"的第一步：知道一个后端服务长什么样。以后你会学真正的框架。）

3.3.2 运行并访问

python3 memo.py &
  • 末尾的 & = "扔到后台运行"（不霸占你的终端）
  • 现在测试：
curl "http://localhost:8000/?action=add&text=今天学会了nginx"
curl "http://localhost:8000/?action=list"

→ 第二条应显示你刚添加的内容。你的程序在 8000 端口活过来啦。

3.3.3 把它变成"正规服务"（systemd 实战）

python3 xxx.py & 的方式很业余：一关窗口就死、重启不自动运行。正规做法是用 systemd 托管：

sudo nano /etc/systemd/system/memo.service

写入：

[Unit]
Description=Memo API Service
After=network.target

[Service]
User=student
WorkingDirectory=/home/student/apps
ExecStart=/usr/bin/python3 /home/student/apps/memo.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target

逐段解释（这是所有 systemd 服务的通用模板）：

  • [Unit]：说明和依赖（After = 网络就绪后再启动）
  • [Service]：怎么跑这个程序。Restart=always = 崩了自动重启（生产环境必备）
  • [Install]：WantedBy=multi-user.target = 允许设置开机自启（固定写法）
  • ⚠️ 注意 User=student 要改成你的用户名（whoami 查看）

然后：

sudo systemctl daemon-reload         # 告诉 systemd "有新服务注册了"（改 unit 文件后必做）
sudo systemctl start memo            # 启动
sudo systemctl status memo           # 看状态 → active (running)
sudo systemctl enable memo           # 开机自启
curl "http://localhost:8000/?action=list"   # 验证

关键理解：这就是"部署一个服务"的标准姿势。你以后部署的 nginx、数据库、比赛的应用……全是这个套路。

3.3.4 用 Nginx 给它当"前台"（反向代理——比赛高频考点！）

现在服务在 8000 端口。用户不可能记端口，我们让 Nginx 把 80 端口的 /memo/ 路径 转给 8000 的服务：

sudo nano /etc/nginx/sites-available/mycompany.conf

把 location / 那个块改成（加一段新的 location）：

    location / {
        try_files $uri $uri/ =404;
    }

    location /memo/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
  • proxy_pass = "把请求转发给谁"。这就是反向代理。
  • proxy_set_header ... = 把访客真实信息传给后端（固定写法，照抄）

    • 四步走：

sudo nginx -t && sudo systemctl reload nginx
curl -H "Host: mycompany.local" "http://localhost/memo/?action=list"

→ 通过 80 端口（Nginx）访问到了 8000 端口（Python）的服务！

为什么这是重点？ 因为"外部端口 80/443 进 → Nginx 转发 → 内部各种服务"是全世界的标准架构。世界赛 Module A 的 A12（HAProxy 反向代理与负载均衡）、韩国赛的 Ingress/ALB 考点，本质都是这件事的变体。

3.4 数据库初体验：装一台 MySQL

几乎每个系统都要存数据。我们来真的装一台数据库，并完成"建库、建表、增删改查"。

3.4.1 安装与管理

sudo apt install -y mysql-server
sudo systemctl status mysql        # 确认 active (running)
sudo mysql                          # 用管理员身份进入数据库（欢迎来到"数据库命令行"）

你会看到提示符变成 mysql> —— 这是MySQL 自己的命令行（和 bash 不是一个东西，exit 退出）。

3.4.2 五板斧：建库、建表、增、查、删

在 mysql> 里逐条执行：

-- 建一个数据库（每个系统一个"仓库"）
CREATE DATABASE company CHARACTER SET utf8mb4;

-- 切进去用它
USE company;

-- 建一张"员工表"（表=一张 Excel 表，列有类型）
CREATE TABLE employees (
    id INT AUTO_INCREMENT PRIMARY KEY,     -- 编号，自动增长，主键（唯一标识）
    name VARCHAR(50) NOT NULL,             -- 姓名，最多50字符，不能为空
    dept VARCHAR(50),                      -- 部门
    salary INT                             -- 工资
);

-- 插入三行数据
INSERT INTO employees (name, dept, salary) VALUES
('张三', '技术部', 15000),
('李四', '市场部', 12000),
('王五', '技术部', 18000);

-- 查询！（SQL 的灵魂）
SELECT * FROM employees;                        -- 查全部
SELECT name, salary FROM employees WHERE dept = '技术部';   -- 带条件查
SELECT dept, AVG(salary) FROM employees GROUP BY dept;      -- 分组算平均 ★ 比赛常见

输出（第三条）：

+--------+-------------+
| dept   | AVG(salary) |
+--------+-------------+
| 技术部 |    16500.0  |
| 市场部 |    12000.0  |
+--------+-------------+

3.4.3 建个"应用专用账号"（安全实践，也是比赛考点）

生产上绝不用 root 连数据库。要给应用建专属低权限账号：

CREATE USER 'memo_user'@'localhost' IDENTIFIED BY 'Memo123!';
GRANT SELECT, INSERT, UPDATE, DELETE ON company.* TO 'memo_user'@'localhost';
FLUSH PRIVILEGES;     -- 让权限立即生效（固定写法）
exit

解释：

  • 'memo_user'@'localhost' = "只允许从本机登录的 memo_user"
  • GRANT ... ON company.* = 只给 company 库的增删改查权，别的库一律不给——最小权限原则（安全的核心思想）

验证用新账号登录：

mysql -u memo_user -p    # 输入刚才设的密码 Memo123!
mysql> USE company; SELECT COUNT(*) FROM employees;   # 能查
mysql> DROP DATABASE company;                          # 试试能不能删库 → 应该被拒绝！(权限不足)

看到"权限不足"的那一刻，你就理解了"权限管理"的意义。

3.4.4 备份数据库（比赛评分点，实务必备）

# 备份（导出整个库到文件）
mysqldump -u root company > ~/apps/company-$(date +%Y%m%d).sql

# 恢复（把备份灌回去）
mysql -u root -e "CREATE DATABASE company2"
mysql -u root company2 < ~/apps/company-*.sql
mysql -u root -e "SELECT COUNT(*) FROM company2.employees"   # 应该还是 3 条

3.5 定时任务 crontab：让服务器自己干活

3.5.1 什么是 crontab？

让命令按时间表自动重复执行：每天凌晨备份、每小时同步、每 5 分钟检查状态……

比喻：给服务器请了个"闹钟管家"。你写好"几点干什么"，它到点自动干。

3.5.2 时间格式（背这张图）

┌──────── 分钟 (0-59)
│ ┌────── 小时 (0-23)
│ │ ┌──── 日 (1-31)
│ │ │ ┌── 月 (1-12)
│ │ │ │ ┌ 星期 (0-7，0和7都代表周日)
│ │ │ │ │
* * * * *  要执行的命令

例子：

30 2 * * *      → 每天凌晨 2:30
0 * * * *       → 每小时整点
*/5 * * * *     → 每 5 分钟（*/5 表示"每5个单位"）
0 9 * * 1-5     → 周一到周五早上 9 点

3.5.3 实战：每天自动备份（把第 1 章的脚本升级）

crontab -e        # 第一次会让你选编辑器，选 nano（对应数字）

在文件末尾加一行（注意：crontab 里的命令要用绝对路径！）：

0 3 * * * /home/student/apps/backup.sh >> /home/student/apps/backup.log 2>&1

（每天凌晨 3 点跑备份脚本，日志追加到 backup.log。>> 和 2>&1 是第 1 章学的重定向——它们在这里是为了"留下执行记录"，不然任务没跑你都不知道）

确保 backup.sh 存在（第 1 章写的）：

# 如果不存在，重建一个：
cat > ~/apps/backup.sh << 'EOF'
#!/bin/bash
mkdir -p /home/student/backups
tar -czf /home/student/backups/apps-$(date +%Y%m%d).tar.gz /home/student/apps 2>/dev/null
find /home/student/backups -name "*.tar.gz" -mtime +7 -delete   # 只保留最近7天
echo "备份完成 $(date)"
EOF
chmod +x ~/apps/backup.sh

查看与管理：

crontab -l          # 看当前有哪些定时任务

比赛关联：世界赛 Module A 的 A10-02 评分点就是"检查备份脚本"——你今天写的东西，就是比赛题的一个答案。

3.6 本章毕业项目：搭一个"个人小站"完整系统

要求：把本章学的全用上，10 个要求全部完成：

  1. 一个静态首页：http://你的IP/，显示自我介绍（用 Nginx 站点配置）
  2. 一个备忘 API：/memo/?action=add&text=xxx 能记东西、?action=list 能看（systemd 托管）
  3. 数据库：建 notes 库和 notes 表（学号、内容、时间），用专属账号 notes_user 访问
  4. 定时任务：每天早上 6 点备份数据库到 ~/backups/
  5. 日志：能随时说出"今天有谁访问过我的网站"（看 access.log）
  6. 防火墙：只放行 22/80/443 端口
  7. （加分）给站点配第二个域名 blog.local，打开是完全不同的页面
  8. （加分）用 curl 假装浏览器访问，验证每个路径的状态码都是 200
  9. （加分）把整个项目的配置、脚本、说明整理成一个文件夹 ~/my-project/，打包备份
  10. 写一份 20 行的"操作手册" ~/my-project/README.md：记录你部署的每一步命令（从今天起养成"做了什么都记下来"的习惯——这是高手的共同习惯）
