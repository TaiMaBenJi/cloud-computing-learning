第 15 章 · 安全加固（把服务器"武装到牙齿"）

官方标准里"网络安全"占世界赛云计算评分的 20%（和问题解决并列最高）。安全不是选修课，是主课。
本章带你做完一套"入侵者骂骂咧咧退出群聊"级加固，并学会云安全的关键操作。
预计学习时间：2-3 周。

15.1 安全心法（先建立思维方式）

三条原则（所有技巧都由它们推导）

  1. 纵深防御：不要指望一道墙拦住所有人。门禁、巡逻、监控、保险箱——一层层加。攻击者翻过一道墙，还有下一道。
  2. 最小权限：任何人/程序/服务，只给"完成它工作所必需"的权限，多一点都不给。（你第 3 章建数据库账号时已经实践过）
  3. 默认不信任（零信任）：不是"内网就安全"，而是"永远验证"。

攻击者的视角（知己知彼）

新手服务器被黑，90% 走这几条路：

  • SSH 弱密码被暴力破解（扫描器全网 24 小时扫 22 端口，root/123456 秒破）
  • Web 应用漏洞（SQL 注入、上传木马——不用懂原理，先会防）
  • 配置裸奔（Redis/MongoDB 无密码暴露公网、S3 桶公开）
  • 不更新（已知漏洞几个月不补）

本章就按这份"黑名单"逐条消灭。

15.2 SSH 加固（第一优先，收益最大）

15.2.1 武装 SSH 的标准六件套

sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak    # 改配置前先备份！
sudo nano /etc/ssh/sshd_config
Port 2222                      # ① 改成非默认端口（扫描器大概率跳过；可选）
PermitRootLogin no             # ② 禁止 root 直接登录 ★必做
PasswordAuthentication no      # ③ 禁止密码登录，只认密钥 ★必做（前提：密钥配好了！）
PubkeyAuthentication yes
MaxAuthTries 3                 # ④ 密码最多试 3 次就断
LoginGraceTime 30              # ⑤ 登录超时 30 秒
AllowUsers ubuntu              # ⑥ 只允许指定用户登录

⚠️ 操作顺序生死攸关：

  1. 先确认你的密钥登录已能用（另开一个终端测试！）
  2. 改配置 → sudo sshd -t（检查语法）→ sudo systemctl restart ssh
  3. 不要关闭当前会话，新开一个终端验证新配置能登录——确认成功后再关旧会话

    4. （经典事故：改完直接重启，然后发现自己被锁在门外。）

15.2.2 fail2ban：自动封杀暴力破解

暴力破解者会在几分钟内尝试上千次密码。fail2ban 盯着日志，发现"同一个 IP 连续失败 5 次"就自动封它。

sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban

# 查状态：看到 Banned IP list 就说明工作正常
sudo fail2ban-client status sshd

常用操作：

sudo fail2ban-client set sshd unbanip 1.2.3.4     # 解封（比如你自己被误封）
sudo fail2ban-client status                        # 看总的监控状态

自测（可选）：故意输错几次密码，然后看 fail2ban-client status sshd 里你的 IP 是不是进黑名单了。

15.2.3 检查有没有人正在撬门

sudo grep "Failed password" /var/log/auth.log | tail -20    # 失败尝试
sudo grep "Accepted" /var/log/auth.log | tail               # 成功登录（看有没有陌生人！）
last | head -20                                             # 最近的登录记录

排障/安全巡检的日常动作。 如果看到陌生 IP 反复尝试——fail2ban 拦着呢，淡定。

15.3 防火墙：只开必需的"门"

sudo ufw status verbose
# 正确姿势：默认拒绝，按需放行
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp       # （或你改后的 SSH 端口）
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

规范：每开一个端口问自己"谁需要访问它？"——

  • 数据库 3306 只允许"应用服务器 IP"，不是所有人（sudo ufw allow from 10.0.1.10 to any port 3306）
  • 管理端口（如 Prometheus 9090）只放行你的办公 IP

    • 云上再复习一次：安全组同样遵循"默认关闭、按源 IP 放行"，两处保持一致。

15.4 系统加固清单（照着打勾）

① 保持更新（最简单也最有效）

sudo apt update && sudo apt upgrade -y
sudo apt install -y unattended-upgrades        # 自动装安全更新
sudo dpkg-reconfigure --priority=low unattended-upgrades    # 选 Yes

② 用户与密码策略

# 检查所有能登录的用户（有没有陌生的？）
awk -F: '$7 !~ /(nologin|false)$/ {print $1, $7}' /etc/passwd

# 发现陌生账号要警惕（黑客爱留后门账号）；确认无用就锁定：
sudo usermod -L 可疑用户名

# 密码强度策略（安装 libpam-pwquality 后配置 /etc/security/pwquality.conf）：
# minlen = 12  最少 12 位
# dcredit/ucredit/lcredit/ocredit = -1  要求数字/大写/小写/符号各至少一个

③ 文件权限审计（重点盯这些）

ls -l /etc/passwd /etc/shadow /etc/ssh/sshd_config
# passwd 应 644，shadow 应 640（或 600），改错的三类危险：
# 全局可写的敏感文件（找出来就改）：
sudo find / -perm -o+w -type f 2>/dev/null | grep -v -E "^/proc|^/sys|^/tmp|^/var/tmp" | head
# 无主文件（可疑痕迹）：
sudo find / -nouser -o -nogroup 2>/dev/null | head
# SUID 程序（提权攻击面，看有没有陌生的）：
sudo find / -perm -4000 -type f 2>/dev/null

④ 审计系统（auditd，进阶但比赛有涉及）

sudo apt install -y auditd
sudo systemctl enable --now auditd
# 监控敏感文件访问示例：
sudo auditctl -w /etc/passwd -p wa -k passwd_changes    # 谁改密码文件，记下来
sudo ausearch -k passwd_changes | tail                  # 查审计记录

⑤ 服务最小化（关掉不用的）

ss -tlnp                # 列出所有正在监听的端口
systemctl list-unit-files --state=enabled    # 所有开机自启的服务
# 原则：每一个"在听的门"和"自启的服务"都要能解释用途，解释不了就关：
sudo systemctl disable --now 没用的服务

15.5 Web 与云安全（比赛重点）

15.5.1 HTTPS 与安全头（网站的门锁与安保）

第 4 章做 HTTPS 是基础。加固再加三件：

# Nginx 配置片段
add_header Strict-Transport-Security "max-age=31536000" always;   # HSTS：强制浏览器永远用 HTTPS
add_header X-Frame-Options "SAMEORIGIN" always;                    # 防点击劫持
add_header X-Content-Type-Options "nosniff" always;                # 防 MIME 嗅探
server_tokens off;                                                  # 隐藏版本号（不给信息）

15.5.2 WAF 概念 + 云实战（韩国赛直接考）

WAF（Web 应用防火墙） = 站在网站前面的"安检门"，拦截攻击流量：

  • 拦 SQL 注入（' OR '1'='1 这种）
  • 拦 XSS（<script> 注入）
  • 拦特征：没有 User-Agent 的请求（韩国赛真题：AWS WAF 的 NoUserAgent_HEADER 规则 → 403）

AWS WAF 实战（在 ALB/CloudFront 上挂）：

  1. WAF & Shield → Create web ACL → 关联 ALB
  2. 加规则：AWS 托管规则组 AWSManagedRulesCommonRuleSet（拦常见攻击）
  3. 加自定义规则：如果不含 User-Agent 头 → Block
  4. 验证：
   curl -A "" -I http://你的站点    # 不带 UA → 应该 403
   curl -I http://你的站点          # 正常 → 200
   curl -I "http://你的站点/?q=' OR '1'='1"   # SQLi 尝试 → 403

这三条命令就是评分脚本检查 WAF 的方式。

15.5.3 云上 KMS 与密钥管理（韩国题考点）

  • KMS = 云上的"钥匙保险柜"，给数据加密用的密钥都在里面（每个服务一把钥匙是良好实践）
  • Secrets Manager = 专门存密码/API Key 的保险柜（能自动轮换）
  • 原则：代码里永远不写密码（第 11 章 Secret 对象就是这个思想）
  • 检查裸露的密钥：grep -r "AKIA" .（AWS 密钥特征开头）——扫到就说明你要出事了

15.5.4 安全组审计（云账户体检）

在 AWS 控制台自查三个高频问题：
① 0.0.0.0/0 开放的端口有哪些？（22/3389 全网开放是常见病）
② 有没有该在私有子网却放了公有子网的数据库？
③ 空着的安全组规则（旧规矩留下的）清理了吗？

15.6 综合实战：加固一台"裸奔"服务器

训练方式（最有效）：故意把一台新装的虚拟机弄"裸"，然后按清单加固，给自己打分。

加固检查表（做完逐项打勾）：

  • [ ] 系统更新到最新 + 开启自动更新
  • [ ] SSH：禁 root 登录、禁密码认证、只允许密钥
  • [ ] fail2ban 运行中，封过至少一个"坏人"
  • [ ] ufw 默认拒绝，只开了 22/80/443
  • [ ] 检查了登录日志和账号列表，无异常
  • [ ] 查了全局可写文件、SUID、无主文件，清理过
  • [ ] 服务最小化：关掉至少一个不需要的服务
  • [ ] 网站有 HTTPS + 三个安全头
  • [ ] 代码/配置里 grep 过敏感字符串，没有明文密码
  • [ ] 有条件的话：AWS 账户开过 MFA、设过预算

每一条都要能回答"为什么"——比赛现场可能会被问，工作中也是你的底气。
