# 真浏览器验收（这是唯一能发现「用户看得见的问题」的方式）

本地文件 + jsdom 的测试**测不出**这些问题，本轮真实踩过的坑：

| 现象 | 为什么 jsdom 测不出 |
|---|---|
| 整段 CSS 显示成正文 | jsdom 把裸 CSS 当普通文本节点，标签照样闭合 |
| 远程页面样式不生效 | jsdom 不做完整 CSS 级联与布局计算 |
| 手机上输入框被键盘遮住 | jsdom 没有视口、没有软键盘 |
| 中文显示成乱码 | 需要真实响应头（`Content-Type` 是否带 charset） |

所以：**改完必须用真浏览器，对着线上地址验一遍。**

## 跑法

```bash
npm i playwright
npx playwright install chromium
node tools/live/live_check.cjs
```

## 它会验什么（当前 40 项）

1. 打开线上 `arena.html`，抓 **console error / pageerror / 失败请求**
2. **读 computed style**：样式表是否加载、body 有没有背景色、标题区有没有高度、按钮有没有宽度
3. **正文长度校验**（在活 DOM 上取 `innerText`，长度过大 = 有内容泄漏成正文）
4. 真点四个 CTA：进虚拟考场 → **真的敲 `whoami` / `ip a` 并验证输出** → 竞赛场 → 里昂 52 行评分点 → 限时考（真点确认框、验倒计时在走）→ 真卷打勾
5. **手机视口**（390×844）：横向溢出、按钮宽度、输入框字号 ≥16px、触控高度
6. 逐页打开其余 8 个页面，各验 状态码 / 控制台 / 可见文本 / 乱码
7. 每一步截图存 `tools/live/_shots/`

## 加断言的纪律

- **只有在活的 DOM 上量**。`cloneNode` 出来的游离节点不套用 CSS，会把隐藏内容算成正文（这个坑我踩过）
- **CSS 泄漏要测特征串**（`display:` / `position:fixed` / `border-radius:`），不是测长度
- **不要用"看起来对"代替断言**：`getComputedStyle` 读到的值才算证据

## 历史教训

本轮这个文件一次就跑出了 2 个真问题：
- 漏了闭合引号的链接改写（改写器 `return` 忘了拼 `m.group(4)`）
- 行内渲染顺序错，`2 + 3 * 4` 里的 `*` 被当斜体，把 `<code>` 拆坏

都是本地测试全绿、真实浏览器才暴露的。
